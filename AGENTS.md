# Project context

- `MASTER_PROMPT.md` is the Russian product specification. It is now plain UTF-8 (previously RTF); read it directly. Consult it before implementation; the constraints below are not the full specification.
- Start with `PROJECT_PLAN.md` (resume point) and `VERIFICATION.md` (verified vs blocked checks). XCUITest automation and full visual/accessibility acceptance are not equivalent to the internal UI smoke test.

## Commands and boundaries

- Use `bash scripts/test.sh` (Swift Testing), `--filter ProgressTests` for focused persistence tests; `bash scripts/build.sh` produces `dist/codelib.app`. `bash scripts/run.sh` keeps development progress in `.local-data/`, not the user's Application Support folder.
- Public brand is lowercase `codelib`; keep the existing bundle identifier, `CodePath` executable/targets and Application Support path for compatibility. `packaging/Info.plist` is the runtime version/stage/build source; release notes live in `LearningCore/Resources/releases.json`. Startup routing uses committed progress: onboarding before automatic history, no history on a fresh install, once per process until acknowledged.
- Сообщения новых коммитов и журнал разработки писать преимущественно по-русски. Старую историю Git не переписывать ради перевода.
- Version-1 setup currently supports a single local profile and Russian UI/course only. Do not offer a fake English switch or claim full CHANGELOG1 onboarding/localization acceptance. Avatar uploads are bounded, downsampled and cropped to a 256px PNG; exports include that photo.
- Scripts select `/Applications/Xcode.app` via `DEVELOPER_DIR` and keep caches/artifacts inside `.build/`; do not change global `xcode-select` or system permissions. Target is macOS 26, tested on arm64.
- `CodePath.xcodeproj` is the native app; its local package dependency is `LearningCore`. The SwiftPM executable target is deliberately named **CodePathApp**, not CodePath, to avoid Xcode test-host resolution conflicts.
- `LearningCore` must stay free of SwiftUI/AppKit. Storage uses versioned Codable JSON with atomic writes, backup, advisory lock, and revision checks; retain unknown exercise IDs and distinguish an empty draft from no draft.
- New editor preferences must decode old schema-1 documents with defaults. Syntax colors use TextKit temporary attributes: never change source text, selection, undo, or copying for styling. The ruler uses the editor's own clip view (ancestor clipping hides offscreen lesson editors), and line/token offsets are UTF-16.
- Author course changes in `scripts/content_*.py`, regenerate with `PYTHONDONTWRITEBYTECODE=1 python3 scripts/generate_content.py`, then run `scripts/verify.sh`. `generate_content.py --check` checks reproducibility without overwriting JSON. Reference compilation/fixtures are developer-only, isolated under `.build/content-check/`.
- Course localization uses text-only `CourseTranslation`; canonical choices/answers, IDs, C++, test cases and progress must not change with labels. The English draft is developer-only (1994/2904 fields, 11 sections / 43 lessons / 204 tasks), NOT shipped. Authors: content_en_01.py through content_en_11.py, each pins SECTION_ID/source SHA256; generate/check with generate_localization.py. Do not silently update fingerprints or permit holes. Production requires complete coverage and reviewed status.
- Developer UI catalog is `localization/ui/Localizable.xcstrings` (209/209 compiler-extracted keys, NOT the full UI). PageHeader/Metric accept LocalizedStringResource; never uppercase a source key or coerce resources to String before Text. Author in ui_en.py; after UI Swift source changes run `bash scripts/extract_ui_localization.sh` (Xcode extraction + real xcstringstool), never fake manifest hashes. Update translations/tests for newly extracted keys; do not freeze the count. Pure --check validates sources/placeholders/reproducibility without requiring Xcode artifacts. The catalog must NOT ship until the full English app is ready; raw .stringsdata contains absolute paths and is forbidden from Git and app resources. Dynamic core/AppModel messages and resources still need explicit localization: inventory in `localization/UI_REMAINING.md`.
- Welcome playback is a finite pure state machine (`ProgrammingGreeting.swift`), not code execution or study activity. `WelcomeCodeView` reads native accessibility flags; `WelcomeCodePanel` accepts explicit values for smoke/previews because those EnvironmentValues are read-only. Reduced motion/Skip enable manual static selection; reduced transparency uses an opaque panel. Do not reintroduce endless animation or mutate system settings in tests.
- The course now includes `content_17.py` (algorithm lab). `verify_content.py --section cpp.section.algorithm-lab` runs focused reference checks; developer-only differential cases live in `algorithm_lab_cases.py`, never in the app. Keep lesson-position persistence optional for schema-1 compatibility and retain unknown lesson IDs.
- Achievement state and profile UUID/date are additive optional schema-1 data. Keep unknown award IDs, never revoke earned awards, backfill legacy progress silently with a recognition date (not invented historical acquisition time). Queue notifications only after successful persistence; study days use local Gregorian date keys, streak calculation must survive DST. Self-review/automatic answers never count as C++ execution. Sound source is `generate_achievement_sound.py`; check reproducibility in verify.sh.
- `CHANGELOG1_STATUS.md` is the current requirement matrix; do not call the full specification complete while English, safe execution and external acceptance remain open. `COMPILER_SECURITY.md` records the current unsandboxed app and required security boundary; do not implement an unsafe Process runner or fake console.
- `scripts/repository_check.py` checks current Git paths/sizes before publication, not secrets/history. `scripts/clean_artifacts.py` defaults to dry-run; `--apply` only prunes completed developer runs, preserving recent reports. Never clean user progress or rewrite Git history to remove artifacts without explicit authorization.
- SwiftPM's resource bundle belongs in the packaged app's **Contents/Resources**, not Contents/MacOS. Build/signature success alone did not catch this; verify an actual launch.

## Implementation constraints

- Keep the native, Russian-language, offline app free of mandatory accounts, telemetry, subscriptions, and web wrappers.
- Before choosing a deployment target or project setup, inspect installed macOS, Xcode, SDKs, and Swift. Full system Liquid Glass targets macOS 26+; do not substitute a custom imitation on older systems.
- First version must **not compile or execute user code**, integrate AI, collect API keys, or simulate either feature. Compiling/running reference C++ solutions during development is explicitly allowed for content verification.
- Never grade free-form C++ by comparing source text with a reference solution. Auto-check only unambiguous answers; code-writing exercises use saved drafts, optional reference solutions, and self-completion clearly distinguished from automatic verification.
- Only C++ has a working course; Python, JavaScript, Java, and Rust are unavailable “Скоро” cards. Keep core course models language-neutral for later expansion.
- Keep structured, versioned course content outside UI components, and learning/checking/progress logic independent of presentation. Persist progress using stable IDs, not array positions; content reordering and schema updates must preserve drafts and results.

## Content and verification

- Teach modern C++17/C++20 progressively to absolute beginners: roughly 80% practice and 20% deeper understanding. Stepik is a pedagogical reference only; do not copy its exercises or materials.
- Reveal hints progressively and keep solutions hidden by default. Verify examples and reference answers; distinguish standard-guaranteed behavior from implementation-specific behavior and undefined behavior.
- Validate content loading, unique IDs, references, and required answer fields; test persistence across relaunch and content changes, not just in-memory state.
- Calculate actual course counts from JSON, not the planning table. Keep `README.md`, `PROJECT_PLAN.md`, and verification results honest about checks that were blocked or not executed.
