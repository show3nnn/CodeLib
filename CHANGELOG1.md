ЧАСТЬ I. РЕБРЕНДИНГ И ИДЕНТИЧНОСТЬ
2. Новое название — codelib
С этого момента наше приложение официально называется:
codelib
Именно так, полностью строчными буквами.
Переименуй его во всех необходимых местах:
	•	Название приложения в macOS.
	•	Dock и Launchpad.
	•	Меню приложения.
	•	Finder.
	•	Приветственный экран.
	•	Заголовки и интерфейс.
	•	Настройки.
	•	Окно «О приложении».
	•	Окно обновлений.
	•	Документация.
	•	Метаданные сборки.
Используй новое название последовательно.
При необходимости переименуй проектные файлы и целевые сборки, но не совершай бессмысленную массовую замену, способную повредить архитектуру.
Важно: переименование не должно уничтожать прежние пользовательские данные.
Сохрани Bundle Identifier, если его изменение не является технически необходимым. Если изменение потребуется, реализуй безопасную миграцию данных и объясни причину.
3. Новый логотип и иконка codelib
Разработай совершенно новую, оригинальную иконку.
Это не временная заглушка, а полноценная часть визуальной идентичности продукта.
Основная идея
На иконке должен быть изображён минималистичный открытый MacBook, практически фронтально, с небольшой перспективой.
Ноутбук должен быть легко узнаваемым даже при небольшом размере.
На его экране — схематично изображён интерфейс нашего приложения codelib.
Не нужно создавать подробный скриншот. Достаточно нескольких основных деталей:
	•	Узкая боковая панель.
	•	Несколько строк кода.
	•	Миниатюрный зелёный индикатор.
	•	Аккуратная центральная область.
	•	Небольшие элементы учебного интерфейса.
Всё должно быть максимально лаконично.
Визуальный стиль
Иконка должна сочетать:
Apple Minimalism × Liquid Glass × Matrix Green
Требования:
	•	Прозрачный фон.
	•	Стеклянные полупрозрачные элементы.
	•	Тонкие серебристо-графитовые грани.
	•	Мягкое естественное освещение.
	•	Лёгкие блики на стекле.
	•	Небольшое зелёное свечение экрана.
	•	Глубину и объём без чрезмерного 3D.
	•	Минимальное количество деталей.
	•	Чистую композицию.
	•	Хорошую читаемость в маленьком размере.
Никаких непрозрачных белых квадратов за логотипом.
Никаких случайных декоративных частиц, чрезмерного свечения, псевдохакерских символов или дешёвых игровых эффектов.
Не добавляй текст «codelib» под ноутбуком внутри иконки.
Не используй emoji и не заменяй полноценный логотип SF Symbol.
Избегай логотипа Apple на корпусе ноутбука. Достаточно узнаваемого силуэта.
Техническая реализация
Создай полноценный ресурс иконки для macOS.
Используй актуальные инструменты Apple, включая Icon Composer, если он доступен и подходит.
Подготовь качественный исходник с прозрачностью и необходимыми размерами, включая 1024×1024.
Если подходящего генератора графики нет, создай векторную иллюстрацию программно, например с помощью SVG, Core Graphics или другого подходящего инструмента, и экспортируй её в формат, используемый проектом.
При наличии возможности создай отдельные слои для системного оформления Liquid Glass.
Учитывай особенности системного маскирования иконок macOS: прозрачность должна сохраняться в исходных ресурсах, а окончательное отображение зависит от платформы.
Проверь отображение в:
	•	Dock.
	•	Launchpad.
	•	Finder.
	•	Окне «О приложении».
	•	Светлом и тёмном оформлениях macOS.
Иконка должна органично выглядеть рядом с другими современными приложениями Apple.
Главный критерий: минималистичный открытый MacBook со стеклянным оформлением и схематичным интерфейсом codelib на экране.

ЧАСТЬ II. СИСТЕМА ВЕРСИЙ И ОБНОВЛЕНИЙ
4. Начало версионирования
С этого момента начинаем вести историю разработки приложения.
Полноценного релиза пока нет, поэтому первая официально отслеживаемая версия:
codelib v0.1.0 Alpha
Используй подход на основе Semantic Versioning.
В дальнейшем:
	•	0.x.x Alpha — активная разработка.
	•	0.x.x Beta — тестирование и стабилизация.
	•	1.0.0 — первый полноценный релиз.
Для системной версии приложения соблюдай требования Apple:
	•	CFBundleShortVersionString — корректный числовой номер.
	•	CFBundleVersion — номер сборки.
	•	Alpha/Beta — отдельное обозначение стадии разработки в пользовательском интерфейсе.
Отображение версии
Добавь компактное отображение версии:
	•	В настройках.
	•	В разделе «О codelib».
	•	В истории обновлений.
Например:
codelib 0.1.0 · Alpha
Версия должна получаться из единого источника, а не дублироваться вручную в разных экранах.
5. История изменений — Changelog
Создай структурированную историю обновлений.
Каждая версия должна содержать:
	•	Номер версии.
	•	Стадию разработки.
	•	Дату выпуска.
	•	Название обновления.
	•	Основные новые функции.
	•	Улучшения.
	•	Исправления ошибок.
Храни изменения так, чтобы их было удобно редактировать при дальнейшей разработке.
Например, в JSON или другой подходящей структуре данных.
Не придумывай фиктивную историю версий.
Для текущей версии создай реальные release notes по фактически реализованным изменениям.
6. Окно «Что нового в codelib?»
После установки новой версии пользователь должен получать красивое окно с основными изменениями.
Вдохновляйся системными экранами Apple, которые представляют новые функции после обновлений.
Внешний вид
	•	Полупрозрачное стеклянное окно.
	•	Крупный заголовок.
	•	Номер версии.
	•	Аккуратная анимация появления.
	•	Несколько карточек с новыми функциями.
	•	Подходящие SF Symbols.
	•	Зелёные акценты.
	•	Кнопка «Продолжить».
Например:
Что нового в codelib 0.1.0?
«Совершенно новый дизайн»
«Пиши и запускай C++»
«Получай достижения»
Логика
При запуске сравни текущую версию с последней просмотренной пользователем версией.
	•	Новая установка: сначала onboarding, без одновременного показа changelog.
	•	Обычный повторный запуск: окно не появляется.
	•	Обновление: показывается история изменений.
	•	Пропущено несколько обновлений: предоставь доступ к изменениям соответствующих версий.
Добавь кнопку «История обновлений» в настройки.
Сохраняй отметку о просмотренных изменениях локально.
Окно должно появляться один раз для каждой новой версии, а не при каждом запуске.

Примеры:
C++

Python
print("Hello, World!")
JavaScript
console.log("Hello, World!");
Swift
print("Hello, World!")
Java
System.out.println("Hello, World!");
Для фрагментов, требующих дополнительного контекста, обеспечь корректный смысл: это примеры строк вывода, а не обязательно самостоятельные полноценные программы.
Анимация
При появлении нового языка:
	•	Текст плавно набирается.
	•	Синтаксис подсвечивается характерными цветами.
	•	Предыдущая фраза растворяется.
	•	Новый язык появляется с мягким переходом.
	•	Можно ненавязчиво показывать результат: Hello, World!
Добавь эффект аккуратного зелёного свечения.
Фон — полупрозрачный, графитовый, стеклянный.
Избегай перегруженных эффектов «Матрицы» с падающими символами.
Всё должно выглядеть элегантно, по-Apple.
Пользователь должен иметь возможность пропустить анимацию.
Поддерживай Reduce Motion.
После приветствия появляется:
Добро пожаловать в codelib.
И кнопка начала настройки.

ЧАСТЬ IV. ПОЛНОСТЬЮ НОВЫЙ ДИЗАЙН
13. Визуальная концепция
Существующий интерфейс слишком напоминает обычное стандартное приложение macOS.
Я хочу, чтобы codelib имел собственный узнаваемый дизайн.
Основная концепция:
Liquid Glass × Apple Minimalism × Matrix Green
Цветовая палитра
Используй:
	•	Полупрозрачный графитовый.
	•	Серебристо-серый.
	•	Матовый почти чёрный.
	•	Холодный белый.
	•	Изумрудно-зелёный.
	•	Мягкий неоново-зелёный для отдельных акцентов.
Зелёный — фирменный цвет.
Но не превращай интерфейс в ярко-зелёную игровую оболочку.
Сохраняй визуальную сдержанность.
Liquid Glass
Используй современные нативные возможности macOS:
	•	Стеклянные боковые панели.
	•	Системные toolbar.
	•	Полупрозрачные панели управления.
	•	Мягкие размытия.
	•	Естественные блики.
	•	Плавные переходы.
	•	Аккуратную глубину элементов.
	•	Системные всплывающие окна.
	•	Мягкие реакции на наведение и нажатие.
Изучи официальные материалы:
https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass
https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/
Используй glassEffect, GlassEffectContainer и другие подходящие современные API там, где это оправдано.
Не имитируй Liquid Glass огромным количеством Blur-слоёв.
Важно: больше Liquid Glass не означает, что вся поверхность приложения должна стать прозрачной.
Применяй стеклянные материалы преимущественно к навигации и элементам управления. Теория и код должны оставаться контрастными и читаемыми.
Фирменные детали
Разработай единую систему:
	•	Радиусов скругления.
	•	Отступов.
	•	Размеров элементов.
	•	Типографики.
	•	Цветовых акцентов.
	•	Теней.
	•	Анимаций.
	•	Состояний кнопок.
