# Что остаётся после 303/303 UI-ключей

## Этап 7: начата рецензия

На текущем снимке извлечены **413/413** ключей компилятора. Вкладки настроек больше не выводятся через русский `rawValue`: для отображения используется `LocalizedStringResource`. Это подготовка, не переключение языка: `PresentationLocale` по-прежнему фиксирован на ru, каталог не входит в приложение.

Для всех 296 условий добавлена автоматическая сверка числовых токенов с русским оригиналом; в теории, условиях, объяснениях и подсказках также проверяется сохранность имён `std::…`. Эти проверки обнаруживают потерянные числа и идентификаторы, но не проверяют смысл, терминологию, знаки операций или качество перевода и не являются содержательной рецензией. Выявленные ранее буквальные Unicode-escape в шести полях истории исправлены; статус всех переводов остаётся draft.

Даты истории форматируются как календарные дни через Gregorian/UTC и явную локаль, без преобразования сохранённой строки и с буквальным fallback для недопустимых дат. Это не перевод истории и не пользовательский выбор языка.

Общие шаблоны C++ и примеры больше не содержат русских учебных комментариев: один нейтральный `// TODO` используется независимо от языка, без перезаписи существующих черновиков. Это не означает, что пользовательский код или комментарии в уже сохранённых черновиках будут переводиться.

Сверка исходников 13.11.2026 для этапа 0.1.14. **Это рабочая инвентаризация, не доказательство полного покрытия интерфейса.** `extraction.json` описывает только строки, которые компилятор извлёк из текущих вызовов SwiftUI/LocalizedStringResource. Перевод всех этих ключей не делает приложение английским: каталог пока не включён в bundle, а обычные динамические String не локализуются автоматически.

## Подготовлено в 0.1.9

`PageHeader` и подписи `Metric` переведены с String на LocalizedStringResource: заголовки главной/каталога/программы/статистики/наград, приветствие с nickname и fallback «Первый урок» теперь видны компилятору. Извлечены и переведены **23 новых ключа** (209 вместо 186). Регистр eyebrow оформляется через `.textCase(.uppercase)` после локализации, не преобразованием ключа. Имя пользователя остаётся буквальным параметром. Тесты проверяют наличие новых ключей в настоящем manifest; это не готовый переключатель языка и не EN-визуальная приёмка.

## За пределами извлечённого каталога

В 0.1.10 добавлены ещё **12 ключей** достижений: категории получают UI-only LocalizedStringResource, скрытые заголовки/описания и исторические/новые даты используют отдельные Text, баннер — интерполируемый шаблон вместо склейки. Названия/описания самих наград пока берутся из RU-определений, как и раньше: системный locale не должен включать частичный English. Привязка к выбранному языку и locale-форматирование остаются будущей работой.

В 0.1.11 добавлены **17 ключей**: Page.title для sidebar/navigationTitle и UI-only подписи ExerciseKind/Completion/Avatar для Text, Label, help и accessibilityLabel. Регистр подписи вида задания оформляется после локализации. Core enum/rawValue остаются прежними, SwiftUI не добавлен в LearningCore. Все эти строки извлечены настоящим Xcode и переведены; проверка RU-fallback не заменяет будущую EN-приёмку.

В 0.1.12 добавлены **46 ключей** ошибок/контекстов/fallback. `ContentError` и `StorageError` несут причины и параметры, `PhotoFailure` — причины фото. `AppFailure` хранит исходный Error и контекст операции; AppModel/photo/profile/root/release не сохраняют готовый перевод в состоянии. `ErrorPresentation` форматирует причину и контекст через native ресурсы с одним явным locale (пока ru), без распознавания русских фраз. Русские errorDescription ядра остаются для совместимости; `.invalid(String)` — только opaque developer/legacy диагностическое сообщение.

В 0.1.13 подготовлены text-only drafts каталога (**10 полей**) и всей истории (**141 поле / 14 версий**) с source SHA256. `ResourceTranslation` сохраняет метаданные и идентичность, отклоняет holes/stale/неверный тип/непроверенный статус. Native UI получил 5 новых ключей ошибок (289 всего). Данные пока вне bundle и **не reviewed**; подключение выбранного языка и полноценная проверка остаются впереди.

В 0.1.14 `PresentationLocale` задаёт ru сценам/динамическим ресурсам/датам/percent; themePreview и native quit alert локализуемы. Системные NSError получают primary summary по domain/code либо generic fallback, opaque диагностика отдельно с disclosure/copy по запросу. Добавлены 14 ключей (303 всего), история151/151 /15 версий. Сохранённые даты/study-day keys не меняются; locale пока фиксирован, plural и English-переключение не реализованы.

## Условия включения English

1. Провести содержательную рецензию **полного draft 2904/2904**: техническое покрытие достигнуто, status не повышается автоматически. Сверить смысл, границы, гарантии C++ и примеры; код/комментарии/fixtures остаются каноническими.
2. После изменений UI выполнить `bash scripts/extract_ui_localization.sh`; число 303 изменится, нельзя заморозить его ради зелёного теста. Не добавлять новые production `ContentError.invalid("готовая фраза")`: нужна типизированная причина и native UI-шаблон.
3. Провести рецензию catalog/release drafts и внешнюю проверку системных ошибок/диагностики. Проверить placeholders, plural-варианты, даты и доступность, а не только отсутствие кириллицы. Каждая новая версия release notes требует обновления авторского перевода и осмысленного пересмотра fingerprint.
4. Только после полной готовности подключить Apple-каталог к app и реальный выбор языка в onboarding/settings. Смена языка не должна перезаписывать черновики, ответы, UUID профиля, награды или позиции.
5. Пройти приложение целиком на RU/EN, включая ошибки, import/export, уведомления, меню, VoiceOver и маленькое окно. Проверки ядра с developer preview не заменяют эту приёмку.

Здесь намеренно нет флага «готово» по числу извлечённых ключей: неполный English не предлагается пользователю.
