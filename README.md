# codelib

Нативная лаборатория C++ для macOS: **17 разделов, 64 урока, 296 оригинальных заданий**, в том числе 199 задач с написанием кода. Русский интерфейс, офлайн, без аккаунтов, телеметрии, подписок и внешних зависимостей.

Текущая версия: **0.1.10 Alpha, сборка 11**. Разработческий перевод покрывает 14 полных разделов — 54 урока / 248 заданий. К штатной локализации подключены категории/скрытые подписи/даты/баннер наград; native UI-каталог содержит 221/221 извлечённых ключей. Остальные динамические сообщения и ресурсы ещё требуют локализации. Оба черновика вне приложения; полный English пока недоступен. Рабочий курс: 17 разделов / 64 урока / 296 задач, новых задач в этом этапе нет. История — `CHANGELOG2.md` … `CHANGELOG11.md`; состояние всего ТЗ — `CHANGELOG1_STATUS.md`.

## Запуск

Требуется **macOS 26+**. Готовая программа: **`dist/codelib.app`**, открывается в Finder как обычное приложение. Локальная ad-hoc подпись предназначена для этого Mac; распространение и notarization не настроены.

Для разработки, с учебными данными **внутри проекта**:

```sh
bash scripts/build.sh
bash scripts/run.sh
```

Скрипт сборки использует Xcode из `/Applications/Xcode.app` через `DEVELOPER_DIR`, не меняет `xcode-select`, не устанавливает инструменты. При ином расположении Xcode задайте `DEVELOPER_DIR` самостоятельно. Собранный артефакт имеет архитектуру компьютера сборки; здесь проверен arm64.

## Работа в приложении

- «Продолжить обучение» возвращает последнее задание. «Программа C++» открывает все темы без блокировок; поиск — по разделам, темам, названиям заданий и навыкам (несколько слов учитываются вместе). Есть фильтры не начатых, текущих и завершённых уроков. Открытие урока возвращает его сохранённую задачу, даже после работы в другом уроке; для старых данных — последнее общее место, первое незавершённое или первая задача полностью пройденного урока.
- Теория и «C++ под микроскопом» доступны рядом с задачами. Намёк, подсказка и разбор раскрываются по желанию, решения изначально скрыты.
- **Встроенного компилятора нет.** Код сохраняется автоматически и отмечается выполненным **самостоятельно**. Эталон не сравнивается с вашим исходником для автоматической оценки. Автопроверка есть у выбора объяснения и предсказания точного вывода.
- Смена/просмотр ответа не стирает прошлое завершение. Для нового прохождения используйте «Повторить»; черновик и история подсказок сохранятся. Изменённый после успеха ответ не выдаётся за заново проверенный.
- Редактор: лексическая подсветка C++, номера логических строк (перенос длинной строки не создаёт новый номер). Tab/Shift+Tab — отступы, Enter — текущий отступ, Control+Tab / Control+Shift+Tab — выход к следующему/предыдущему контролу, Cmd+C — стандартное копирование. Есть кнопка копирования всего кода. Длинные строки переносятся.
- Cmd+Return — проверить однозначный ответ, Cmd+[ / Cmd+] — предыдущая/следующая задача, Cmd+Shift+R — продолжить, Cmd+, — настройки.
- Настройки: системная/светлая/тёмная тема, размеры текста/кода, включение подсветки и номеров строк, экспорт/импорт JSON и подтверждаемый сброс. Новые настройки получают значения по умолчанию при чтении прежних файлов версии 1, не сбрасывая результаты. Python, JavaScript, Java, Rust имеют только статус «Скоро».
- При первом запуске — приветствие, локальное имя и аватар, выбор темы. Пять подсвеченных строк набираются и сменяются через плавное исчезновение, последовательность заканчивается и не работает бесконечно. Skip/Reduce Motion показывают полную строку сразу и дают ручной просмотр всех пяти примеров; Reduce Transparency заменяет стекло непрозрачной панелью. Это декоративные примеры, не выполнение кода. Старому пользователю сразу предлагается заполнить недостающий профиль без сброса заданий. Пройденные шаги сохраняются кнопкой «Далее»; незавершённая настройка возобновляется.
- Профиль: Unicode-имя 1–30 символов, инициал, три готовых аватара или собственное фото. Фото PNG/JPEG/HEIC до 12 МиБ/40 Мп уменьшается, кадрируется и сохраняется как PNG 256×256 без переноса метаданных исходника. Есть масштаб и смещение кадра. Имя и аватар можно изменить в настройках. Профиль один, проверки глобальной уникальности и облачной регистрации нет.
- Достижения: отдельная коллекция 24 наград, категории, прогресс, даты, секретная награда и подробные карточки. Условия основаны на реальных завершениях/проверках/черновиках и календарных днях работы с заданиями. Самопроверка не считается исполнением C++. Старый прогресс учитывается без баннеров; дата помечена как дата учёта, не вымышленное время прежнего получения. Новые награды показываются последовательно только после сохранения на диск и не выдаются снова. Оригинальный короткий звук выключается в настройках.
- Настройки шрифта имеют предпросмотр текста/кода и отдельный сброс к стандартным размерам без удаления прогресса. «Сбросить код» в редакторе требует подтверждения и сохраняет исторические отметки/подсказки.
- Меню приложения и настройки открывают «О codelib» и «Историю обновлений». Версия/стадия/сборка берутся из `packaging/Info.plist`; заметки — из `Sources/LearningCore/Resources/releases.json`. Закрытие истории не помечает её прочитанной; отдельная кнопка сохраняет отметку с обработкой ошибки и повтором. После обновления история показывается только после завершения настройки; на новой установке сразу открывается обучение. Прочитанная история не открывается повторно.

## Данные и восстановление

При обычном открытии `.app` прогресс хранится в `~/Library/Application Support/CodePath/progress.json`. При запуске через `scripts/run.sh` или shared Xcode scheme — в `.local-data/progress.json`. Переменная `CODEPATH_DATA_DIR` позволяет явно выбрать папку; тесты используют отдельные каталоги только внутри `.build/`.

Папка `CodePath`, Bundle ID `local.codepath.learning`, внутренние target/executable намеренно не переименованы: ребрендинг не создаёт новое пустое хранилище. Актуальный артефакт — `codelib.app`. Профиль, уменьшенное фото, незавершённая настройка и отметка обновления входят в локальный JSON, backup и экспорт; учитывайте это при передаче экспорта другим людям.

UUID профиля, награды и даты активности тоже входят в экспорт. UUID сохраняется при редактировании имени/аватара; дата создания новых профилей записывается, а неизвестная дата прежних профилей не выдумывается. Явный полный сброс удаляет весь профиль/награды вместе с учебным прогрессом после подтверждения.

Прежнюю серию календарных дней нельзя восстановить из одной даты последнего занятия: она не выдумывается при миграции. История дней для наград накапливается с этого обновления при работе с заданиями.

`progress.json.backup` — предыдущая сохранённая версия. Запись атомарная, с advisory lock и проверкой версии файла между экземплярами; неизвестные ID не удаляются при изменении контента. Будущая/повреждённая схема не подменяется пустым прогрессом. При ошибке записи черновик остаётся в памяти, показывается предупреждение, доступны повторная попытка и экспорт; выход требует подтверждения потери несохранённого.

Если прогресс повреждён, экран восстановления может вернуть резервную копию под той же файловой блокировкой, что используется обычной записью. Оригинал перед заменой сохраняется рядом как `progress.json.preserved-<UUID>`. Если копия тоже некорректна или файл занят, рабочий прогресс не перезаписывается. Не удаляйте файлы вручную ради устранения ошибки. Экспортируйте прогресс перед сбросом/импортом: резервная копия — не бесконечный архив. Для экспорта нужно выбрать отдельный файл: main/backup/lock/preserved защищены от случайной замены, включая символьные и жёсткие ссылки на рабочие файлы. Импорт **заменяет**, а не объединяет состояние; это подтверждается перед выбором файла.

## Xcode и устройство проекта

Откройте **`CodePath.xcodeproj`**, shared scheme **CodePath**, destination **My Mac**, Run. Отдельно `Package.swift` можно открыть для работы с ядром и Swift Testing.

Проверка release-сборки именно Xcode-проекта: `bash scripts/xcode-build.sh`; её артефакт — `.build/xcode/Build/Products/Release/codelib.app`.

- `Sources/LearningCore/` — модели каталога/курса, валидатор, правила проверки, навигация и сохранение; без SwiftUI/AppKit.
- `Achievements.swift` — определения и условия 24 наград отдельно от UI. Русские/английские тексты самих определений подготовлены, но это не означает готовность английского приложения. `scripts/generate_achievement_sound.py` воспроизводит авторский WAV, `--check` входит в verify.sh.
- `Sources/CodePath/` — SwiftUI-экраны и AppKit-редактор; `AppModel` координирует действия и показывает ошибки.
- `Sources/LearningCore/Resources/` — версионированные `course.json`, `catalog.json`, `releases.json`, включённые в offline bundle.
- `scripts/generate_icon.swift` — программный оригинал иконки открытого ноутбука с прозрачным фоном; PNG 16–1024 px в `.build/CodePath.iconset/`, ICNS для Xcode в `packaging/CodePath.icns` (имя ресурса сохранено).
- `Tests/` — ядро и координация приложения. `UITests/` — отдельный XCUITest пользовательского сценария.
- `PROJECT_PLAN.md` — этапы, журнал, точка продолжения; `VERIFICATION.md` — результаты и ограничения проверки.
- `localization/` — разработческие материалы, не ресурсы приложения. 14 разделов en: 2437/2904 полей, 54 урока / 248 заданий; UI-каталог: 221/221 извлечённых ключей. Форматы и проверки — `localization/README.md`; оставшиеся динамические строки/ресурсы — `localization/UI_REMAINING.md`.
- `scripts/content_17.py` — новый блок: префиксные суммы/разности, окна, два указателя, бинарный поиск и мини-проект вместимости. `scripts/algorithm_lab_cases.py` — только разработческие независимые переборные проверки, не примеры в интерфейсе и не выполнение пользовательского кода.

## Проверки

```sh
# Проверка соответствия JSON авторским данным, без изменения файлов
PYTHONDONTWRITEBYTECODE=1 python3 scripts/generate_content.py --check

# Все тесты ядра и модели приложения; отдельный тест по имени
bash scripts/test.sh -Xswiftc -warnings-as-errors
bash scripts/test.sh --filter ProgressTests

# Только разработческая проверка эталонов, НЕ выполнение пользовательского кода
PYTHONDONTWRITEBYTECODE=1 python3 scripts/verify_content.py
PYTHONDONTWRITEBYTECODE=1 python3 scripts/verify_content.py --section cpp.section.algorithm-lab

# Реальные окна/редактор, восстановление и обновление тремя процессами; изолированные данные
bash scripts/ui-smoke.sh

# Вся доступная регрессия и release-сборка
bash scripts/verify.sh
```

Перед публикацией в GitHub:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 scripts/repository_check.py
# Сначала только посмотреть план очистки завершённых диагностических прогонов
PYTHONDONTWRITEBYTECODE=1 python3 scripts/clean_artifacts.py
# Удалить старые прогоны, оставив два последних каждого вида
PYTHONDONTWRITEBYTECODE=1 python3 scripts/clean_artifacts.py --apply
```

Проверка репозитория входит в `verify.sh`: отслеживаемые/неигнорируемые сборки, локальные данные, Python-кеши и файлы больше 20 МиБ останавливают проверку. Это не сканер секретов и не аудит прежней истории Git. Очистка затрагивает только завершённые прогоны внутри `.build/ui-smoke` и `.build/release-launch`; `.local-data`, текущая `.app`, кеши сборки и исходники сохраняются. Без `--apply` ничего не удаляется.

Результаты компиляции C++ и файловые fixtures — `.build/content-check/report.json`; внутренние UI-отчёты — `.build/ui-smoke/run-*/screenshots/`. C++ проверяется в **C++17 и C++20**, с предупреждениями как ошибками и UndefinedBehaviorSanitizer. Все файлы эталонов создаются в изолированных подпапках `.build`, не в учебных данных.

`bash scripts/xcode-test.sh` собирает XCUITest, но **его исполнение здесь блокируется macOS automation mode**. Внутренний UI-smoke не подменяет реальные клики, VoiceOver или окончательную визуальную приёмку. Разрешения системы автоматически не изменяются. Подробности в `VERIFICATION.md`.

## Добавление материалов

Авторские данные находятся в `scripts/content_01.py` … `scripts/content_17.py`; helpers уменьшают повторение формата, а не генерируют задачи заменой чисел. После осмысленного изменения:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 scripts/generate_content.py
bash scripts/verify.sh
```

Не меняйте существующие ID при редактировании текста или перестановке уроков. Новая задача получает новый ID; последовательность не является идентификатором. Обновляйте зависимости тем. Для code-задачи обязательны эталон, две ступени подсказок, объяснение, навыки, сложность, примеры. Файловые примеры задаются `files` и `expectedFiles`; интерфейс показывает их отдельно от cin/cout. Примеры `output` должны содержать **полную** программу в starter и проверяемый ответ, не UB.

Если редактируете JSON напрямую, перенесите изменения в авторские модули: `--check` обнаруживает расхождение и не затирает его автоматически. При изменении схемы хранения нужна явная миграция и тесты; текущая версия 1 — первый формат. Новая версия контента не должна сбрасывать состояние пользователей.

## Дальнейшее расширение

Локализация продолжается: text-only overlay не меняет ID, C++, ожидаемые ответы или сохранённые значения выбора. 14 разделов покрыты полностью, но ещё нужны 10 уроков / 467 полей и динамические UI-сообщения/ошибки/ресурсы. Все 221 извлечённый ключ переведены, но это не полный интерфейс. Native String Catalog проверен Apple xcstringstool и пока не включается в приложение. Рабочий загрузчик отвергает draft/неполный/устаревший курс, English не предлагается в настройках. Полный внешний визуальный/VoiceOver-аудит остаётся незавершённым.

Модели не привязаны к C++ по именам типов. Новый реальный курс потребует загрузчика соответствующего ресурса и выбора курса; одних карточек недостаточно. Настоящий исполнитель кода в будущем должен стать отдельным изолированным модулем с ограничением ресурсов; AI — отдельной интеграцией с безопасным хранением ключей. **Ни один из этих модулей сейчас не реализован или сымитирован.**

Фактическая граница безопасности и критерии допуска будущего compiler/runner описаны в `COMPILER_SECURITY.md`. Установленный clang и developer-проверка эталонов не означают безопасную готовность к пользовательскому запуску.

Подсветка — только оформление, не парсер и не диагностика: она различает ключевые слова, базовые типы, числа, директивы, комментарии и обычные/raw-литералы; не проверяет корректность программы и не оценивает решение. Цвета адаптируются к теме. Номера строк не попадают в текст, копирование или прогресс. Доступность системных контролов используется нативно, но окончательные ручные проверки VoiceOver/Full Keyboard Access и full-screen ещё нужны.
